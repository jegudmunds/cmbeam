Gagnaúrvinnsla¶

Reiknifræði, gagnaúrvinnsla, gagnavísindi eru allt einhvers konar hrærigrautur af stærðfræði, tölvunarfræði og líkanagerð. Við ætlum að reyna að hræra aðeins í þessum graut í þessum fyrstu köflum námskeiðsins. Það má finna stutta umfjöllun um gagnavísindi í Python fyrirlestrarnótunum í Edbook og þar eru grunngreinar reiknifræðinnar brotnar upp í nokkra flokka, meðal annars:

  • Töluleg greining (e. numerical analysis, computational science stundum notað sem samheiti)

  • Töluleg bestun (e. numerical optimization), undirgrein tölulegrar greiningar og aðgerðagreiningar, oft er líka talað um bestunarfræði (sem fjallar einnig um fræðilega bestun)

  • Stærðfræðileg líkansmíð (e. mathematical modelling), þverfaglegt svið milli flestra fræðasviðanna í þessum lista auk annarra, t.d. verkfræði, eðlisfræði og efnafræði

Dæmi um verkefni í gagnavísindum¶

Verkefni tengd gagnaúrvinnslu eru afar fjölbreytt og því geta lausnir þeirra oft verið sértækar. Þó eru nokkrar tegundir af verkefnum sem birtast reglulega, óháð verksviðum.

Nokkur dæmi:

  • Gagnameðferð (e. data manipulation)
  • Línuleg og ólínuleg aðhvarfsgreining (e. linear / non-linear regression)
  • Hreinsun og síun (e. filtering) á gögnum til þess að draga úr ómarktækum sveiflum
  • Tímaraðagreining, leitni (e. trend) og lotubundnar sveiflur
  • Höfuðþáttagreining (e. principal component analysis)
  • Sennileikamat (e. maximum likelihood estimate)

Mörg þessara atriða bregður stuttlega fyrir í stærðfræðinámskeiðum við Háskóla Íslands. Bæði línuleg aðhvarfsgreining og höfuðþáttagreining er kaflar í línulegri algebru og tölulegri greiningu. Sennileikamat birtist meðal annars fyrir í líkinda og tölfræði. Umfjöllunin í þessari vinnubók fer á hundavaði yfir fyrstu fjóra punktana úr listanum hér fyrir ofan.

NumPy¶

NumPy snýst fyrst og fremst um ndarray hlutinn (e. object) sem geymir tölulegar upplýsingar á fylkjaformi og ýmis konar föll sem vinna með þess fylki. Fylkin geta haft margar víddir, ekki bara eina eða tvær víddir eins og við eigum að venjast úr grunnnámskeiðum í línulegri algebru.

Þeir sem nota Python í gagnavísindaheiminum verða að hafa sterk tök á NumPy forritasafninu (e. library). Python hefur ekki orð á sér fyrir að vera hratt forritunarmál og það kemur því kannski ekki á óvart að öll helstu NumPy föllin eru í raun C föll í Python umbúðum (e. wrapper).

Það er alls ekki sniðugt að nota Python lykkjur (sbr. for lykkja) til þess að vinna úr tölulegum gögnum þar sem slíkar aðgerðir keyra almennt mjög hægt. Það er miklu betra að setja gögnin upp sem NumPy fylki og beita síðan föllum úr NumPy safninu á þessi gögn.

Byrjum á því að flytja inn NumPy forritasafnið:

import numpy as np
print("NumPy útgáfa:", np.__version__) # Alltaf gott að vita hvaða útgáfa er notuð

NumPy útgáfa: 1.17.5

Vigrar vs listar¶

Áður en að við höldum lengra þá skulum við bera saman NumPy vigra og Python lista. Það er afar freistandi að nota Python list hluti til þess að vinna með safn af tölum en það veldur því að kóðinn keyrir talsvert hægar. Þetta getur orðið sérstaklega slæmt þegar stærð talnasafnsins eykst.

Við skulum bera saman þessar tvær leiðir til þess að vinna með tölur.

Byrjum á því að sækja time forritaeininunga til að mæla tímalengdir.

import time

Gefum okkur að við séum að vinna með safn af mælingum á spennu (e. voltage). Búum til lista með n_meas mælingum með aðferð sem kallast List Comprehension. Takið eftir að for-lykkjan er inni í hornklofunum!

n_meas = 10**5
voltage_list = [10 + i*0.1 for i in range(n_meas)]

Nú skulum við reikna samsvarandi afl með jöfnunni $P = V^2/R$ og nota til þess for lykkju og mæla tímann sem þessi aðgerð tekur.

start_time = time.time()
power_list = []
R = 7.0
for voltage in voltage_list:
    power = voltage**2 / R
    power_list.append(power)
list_time = time.time() - start_time

Sjáum hvað það tók langan tíma:

print(f"Python list took: {list_time:.4f} seconds")

Python list took: 0.0287 seconds

Nú notum við listann okkar til þess að búa til NumPy vigur.

voltage_array = np.array(voltage_list)

Hér fyrir neðan framkvæmum við sömu reikninga og í for-lykjunni á undan.

start_time = time.time()
power_array = voltage_array**2 / R
numpy_time = time.time() - start_time

Berum á endanum saman tímann sem það tók að framkvæma þessa útreikninga.

print(f"NumPy took: {numpy_time:.4f} seconds")
print(f"NumPy is {list_time/numpy_time:.1f}x faster!")

NumPy took: 0.0010 seconds
NumPy is 28.5x faster!

Prófið að breyta fjölda mælinga og sjá hvernig tíminn sem það tekur að framkvæma þessa reikninga með aðferðunum tveimur að ofan þróast.

NumPy reynist talsvert hraðari heldur en Python listar vegna þess að NumPy keyrir á þýddum (e. compiled) vélarkóða (e. machine code) á meðan Python listar byggja á kóða sem túlkar hverja línu fyrir sig á meðan kóðinn keyrir.

Sýn vs afrit¶

Allir NumPy vigrar sem við skilgreinum í kóða vísa í einhverja staðsetningu í minni tölvunnar. Þetta sést skýrt af dæminu hér fyrir neðan:

arr = np.array([10, 20, 30])
data_address = arr.__array_interface__['data'][0]

print(f"Decimal address: {data_address}")
print(f"Hex address:     {hex(data_address)}")

Decimal address: 2704698837536
Hex address:     0x275bc9d0a20

Við ætlum ekki að stressa okkur á þessum tölum hér fyrir ofan en tökum þó fram að í NumPy er munurinn á view() og copy() eftirfarandi:

  • View (sýn): Nýtt fylki sem deilir sömu gögnum í minni og upprunalega fylkið. Breytingar á öðru fylkinu geta því haft áhrif á hitt.
  • Copy (afrit): Nýtt, sjálfstætt fylki með afriti af gögnunum. Breytingar á afritinu hafa ekki áhrif á upprunalega fylkið.

Við sjáum að view() deilir gögnum en copy() býr til sjálfstætt afrit.

Skoðum nokkur dæmi:

# Sýn inn í fylki
a = np.array([1, 2, 3, 4])
b = a.view()
b[0] = 99
print(a)  # [99  2  3  4]

[99  2  3  4]

# Afrit af fylki
a = np.array([1, 2, 3, 4])
b = a.copy()
b[0] = 99
print(a)  # [1 2 3 4]
print(b)  # [99  2  3  4]

[1 2 3 4]
[99  2  3  4]

# Sneiðing gefur sýn
a = np.array([1, 2, 3, 4, 5])
b = a[1:4]
b[0] = 99
print(a)  # [1 99 3 4 5]

[ 1 99  3  4  5]

Oftast þurfum við ekki að hafa áhyggjur af þessum hugtökum en það getur þó verið gott að vita af þessu þegar við leitum að villum í kóða. Sjá dæmi fyrir neðan:

# Upprunaleg mæligögn
data = np.array([10, 20, 30, 40, 50])

# Veljum fyrstu þrjú gildin
subset = data[:3]

# Breytum gildunum
subset *= 2

print('subset:', subset)
print('data:', data)

subset: [20 40 60]
data: [20 40 60 40 50]

Breytt um lögun fylkja¶

Hægt er að breyta lögun (e. shape) fylkis án þess að breyta gögnunum sjálfum. Hér er dæmi um nokkur föll sem hægt er að nota:

  • reshape skilar nýju fylki með nýrri lögun
  • ravel skilar „flöttu“ sýnifylki (view) þegar mögulegt
  • flatten skilar alltaf afriti (copy)

Ath: NumPy föll sem verka á ndarray hlutinn skila ýmist sýn eða afriti (sjá dæmi fyrir neðan):

# Búum til einfalt 1D-fylki
a = np.arange(12)
print("a:", a)
print("shape a:", a.shape)

# Breytt um lögun á 3 x 4 fylki
A = a.reshape(3, 4)
print("\nA = a.reshape(3, 4):\n", A)
print("shape A:", A.shape)

# Ravel - skilar „flatri“ sýn (ef hægt)
r = A.ravel()
print("\nr = A.ravel():", r)

# Flatten - skilar alltaf afriti
f = A.flatten()
print("f = A.flatten():", f)

# Breytum r og skoðum hvort A breytist (vegna views vs copy)
r[0] = 999
print("\nEftir breytingu á r[0] = 999:")
print("r:", r)
print("A:", A)
print("f (afrit):", f)

Útvíkkun (e. broadcasting)¶

Útvíkkun (e. broadcasting) leyfir okkur að framkvæma reikniaðgerðir á fylkjum með ólíkri lögun án þess að þurf að reiða okkur á venjulegar Python lykkjur. NumPy „útvíkkar“ víddir þegar það er hægt til að samræma stærðir. Skoðum nokkur dæmi:

# Búum til 3x3 fylki
A = np.ones((3, 3))
# Búum til 1D vigur
b = np.array([1, 2, 3])

print("A:\n", A)
print("b:", b)

# Broadcasting: b er „víkkað út“ yfir raðir A
C = A + b
print("\nA + b (broadcasting):\n", C)

# Annað dæmi með mismunandi lögun
x = np.arange(3).reshape(3, 1)   # shape (3,1)
y = np.arange(4)                 # shape (4,)
print("\nx shape:", x.shape, "y shape:", y.shape)

D = x + y  # verður shape (3,4)
print("x + y (broadcasting):\n", D)

 [1. 1. 1.]
 [1. 1. 1.]]
b: [1 2 3]

A + b (broadcasting):

 [2. 3. 4.]
 [2. 3. 4.]]

x shape: (3, 1) y shape: (4,)
x + y (broadcasting):

Vísun og sneiðing¶

Við getum valið hluta gagna með:

  • Hefðbundinni sneiðingu (e. slicing) með hjálp (:)
  • Boolean mynstrun (e. masking)
  • Vísun (e. indexing) í hluta af lista (e. list) eða ndarray.
x = np.arange(10)
print("x:", x)

# Hefðbundin sneiðing
print("\nx[2:7]:", x[2:7])

# Sleppum skrefum (step)
print("\nx[::2] (annur hvert stak):", x[::2])

# Sækjum þriðja og annað síðasta stakið í vigri
print("\nx[-3:-1]:", x[-3:-1])

# Sækjum síðasta stakið í vigri
print("\nx[-1]:", x[-1])

# Boolean mynstrun: veljum slétt tölugildi
mask = (x % 2 == 0)
print("\nmask (x % 2 == 0):", mask)
print("x[mask] (slétt):", x[mask])

# Vísun framkvæmd á listum
idx = [1, 3, 7]
print("\nidx:", idx)
print("x[idx]:", x[idx])

  • np.hstack staflar eftir dálkum.
a = np.array([1, 2, 3])
b = np.array([4, 5, 6])

B = np.arange(6, 12).reshape(2, 3)
print("\nA:\n", A)
print("B:\n", B)

# Lóðréttur stafli (raðir)
V = np.vstack([A, B])
print("\nnp.vstack([A, B]):\n", V)

H = np.hstack([A, B])
print("\nnp.hstack([A, B]):\n", H)

C0 = np.concatenate([A, B], axis=0)  # eins og vstack

Dæmi um sniðugar NumPy aðgerðir¶

Hér fyrir neðan eru nokkur dæmi um verkefni sem stundum bregður fyrir þegar unnið er með NumPy. Reyndur Python notandi ætti að hafa séð flest af þessu áður.

Finna það stak sem kemst næst ákveðnu gildi¶

Þú ert að vinna með einhvern vigur og vilt komast að því hvaða stak í vigrinum kemst næst tölu með ákveðið gildi. Þetta getur verið mjög gagnlegt þegar við viljum vísa í gögn sem falla á einhverju bili. Endilega skoðið hvað argmin fallið gerir.

x = np.linspace(0, 1, 100)
xp = 0.573
idx = np.argmin(np.abs(x-xp))
print(f"Stak sem sem kemst næst {xp} er stakið {x[idx]:.4f}")

Stak sem sem kemst næst 0.573 er stakið 0.5758

Finna stök í vigri sem uppfylla Boolean skilyrði¶

Það getur verið gagnlegt að afmarka hluta gagna sem uppfylla ákveðin skilyrði. Þetta er oft gert með vigrum af Boole tagi (sjá dæmi fyrir neðan).

arr = np.array([10, 20, 30, 40, 50])
idx = arr > 25  # Klippirammi (e. mask) af Boole tagi
print(arr[idx]) # [30 40 50]

[30 40 50]

Finna einstök gildi í vigri og fjölda tilfella¶

Stundum getur verið gott að sjá hvaða einstöku (e. unique) gildi birtast í gagnasafninu okkar. Það er gert með unique fallinu.

arr = np.array([1, 2, 2, 3, 4, 4, 4, 5])
unique_vals, counts = np.unique(arr, return_counts=True)
print(unique_vals)  # [1 2 3 4 5]
print(counts)       # [1 2 1 3 1]

[1 2 3 4 5]
[1 2 1 3 1]

Finna gildi í vigri sem eru ekki núll¶

Eins er til gagnlegt fall sem skilar vísum (e. index) úr vigrinum þar sem vigurinn er ekki núll.

arr = np.array([0, 2, 3, 0, 4])
idx = np.nonzero(arr)
print(idx[0])
print(arr[idx])

[1 2 4]
[2 3 4]

    return np.convolve(arr, np.ones(window_size)/window_size, mode='valid')

Scipy¶

NumPy forritasafnið skilgreinir grunneiningar reiknifræðinnar, safn af einhvers konar frumeiningum sem eru undirstöður allrar tölulegrar vinnu. Scipy forritasafnið byggir á þessum grunneiningum og skilgreinir út frá þeim ýmis sérhönnuð tæki sem engin gagnavísindamanneskja getur verið án. Dæmi um þessi verkfæri eða föll eru meðal annars:

  • scipy.linalg.solve — Finnur lausn á línulegum jöfnuhneppum
  • scipy.integrate.quad — Töluleg heildun
  • scipy.optimize.minimize — Finnur lággildi falls (t.d. notað við bestun)
  • scipy.optimize.curve_fit — Mátar gögn við líkan með aðferð minnstu fervika (líka notað við bestun)
  • scipy.fft.fft — Reiknar hraða Fourier-ummyndun

Við munum kynnast sumum af þessum föllum á næstu vikum en við ætlum að byrja á brúunarverkefnum (e. interpolation) í þessari viku.

Brúun¶

Það er mjög algengt að fá í hendurnar tvo vigra x og y sem skilgreina inntaksbreytu og eitthvert fall $y = f(x)$. Svo kemur kannski í ljós að gögnin spanna ekki nægilega langt bil eða inntaksbreytan ætti að vera af hærri upplausn. Þá verðum við að grípa til þess að nota brúun. Þið lærið um fræðilegar hliðar brúunar í tölulegri greiningu en þegar unnið er með gögn þá þarf stundum bara að finna eitthvað fall sem virkar hratt og örugglega.

Það má finna mjög góða umfjöllun um brún í Scipy handbókinn sem ég mæli með að þið skoðið.

Brúun snýst um að finna eða kannski réttara sagt búa til nýja gagnapunkta út frá því gagnasafni sem er þegar til staðar. Þegar við erum að brúa gögn þá erum við óbeint að gera ráð fyrir því að til sé einhvers konar stærðfræðilega lýsing fyrir upprunalega gagnsafnið. Einfaldasta aðferðin er línuleg brúun (e. linear interpolation). Þá gerum við ráð fyrir að gögnin breytist línulega á milli tveggja mælipunkta.

Ef við höfum tvo punkta $(x_0,y_0)$ og $(x_1,y_1)$ má áætla gildið $y(x)$ með jöfnunni:

$$ y(x) = y_0 + \frac{y_1-y_0}{x_1-x_0}(x-x_0). $$

Þetta er auðvitað bara jafna beinnar línu sem liggur í gegnum punktana tvo.

Einföld brúun með NumPy¶

NumPy býður upp á fallið np.interp() til að framkvæma línulega brúun.

# Mæld gögn
x = np.array([0, 1, 2, 3, 4])
y = np.array([2, 4, 3, 7, 6])

# Áætla gildi við x = 1.5

y_nytt = np.interp(x_nytt, x, y)

Úttakið er 3.5, því gildið við $x=1.5$ liggur mitt á milli mæligildanna 4 og 3.

Fallið np.interp() tekur þrjú meginviðföng:

  • x_nytt: Staðsetning þar sem við viljum áætla ný gildi.
  • x: Staðsetningar þekktra mælipunkta, raðað í vaxandi röð.
  • y: Mæld gildi sem samsvara punktunum í x.

Takmarkanir línulegrar brúunar

Línuleg brúun er einföld og fljótleg en hefur nokkra annmarka:

  1. Hún gerir ráð fyrir línulegri breytingu á milli mælipunkta.
  2. Hún getur ekki endurskapað hátíðnisveiflur sem mælingarnar ná ekki að sýna.
  3. Ferillinn er samfelldur en halli hans getur breyst skyndilega við mælipunktana (fyrsta afleiðan er ekki samfelld).

Einnig þarf að gæta að því að brúun og framreikningur eða bryggjun (e. extrapolation) eru ekki það sama. Brúun áætlar gildi innan mælibilsins en bryggjun áætlar gildi utan þess. Ef fallið `np.interp()` er beðið um að skila gildi utan mælibilsins skilar það venjulega gildinu við næsta endapunkt án þess að framlengja línuna.

Brúun með margliðum af hærra stigi¶

Línuleg brúun tengir mælipunkta með beinum línustrikum. Stundum viljum við hins vegar fá mýkri feril sem lýsir betur samfelldum breytingum í gögnunum.

Með plæsibrúun (e. spline interpolation) eru margliður notaðar til að tengja mælipunktana saman. Algengt er að nota þriðja stigs splæsibrúun (e. cubic spline interpolation), þar sem þriðja stigs margliða er notuð á milli samliggjandi mælipunkta.

Í SciPy má nota fallið scipy.interpolate.make_interp_spline() til að framkvæma slíka brúun. Skoðum dæmið fyrir neðan:

# Þéttara bil fyrir brúun

# Línuleg brúun

# Þriðja stigs splæsibrúun
spline = make_interp_spline(x, y, k=3)
y_spline = spline(x_nytt)

# Teiknum niðurstöðurnar
plt.plot(x, y, 'ko', label='Mæld gögn')
plt.plot(x_nytt, y_lin, '--', label='Línuleg brúun')
plt.plot(x_nytt, y_spline, '-', label='Þriðja stigs brúun')

Tímaraðagreining¶

Þessi undirkafli fjallar stuttlega um grunnhugtök í tímaraðagreiningu.

Kynning¶

Það er hægt að taka óteljandi dæmi um gildi og gagnsemi tímaraða í lýsingu á umhverfinu okkar. Við reiðum okkur að sjálfsögðu á tímaraðir þegar við viljum öðlast skilning á tímaþróun ýmissa kerfa, m.a. hreyfingu fjármálamarkaða.

Skilgreiningar¶

Tímaröð er tvenndarruna: $(t_1, y_1), \dots (t_m, y_m)$

Henni má lýsa með tveimur vigrum af sömu lengd, annars vegar vigri sem táknar tíma, $\mathbf{t} = [t_1, \dots, t_m]$, oftast mældur með reglulegu millibili, og hins vegar vigri sem táknar einhvers konar mælingar, $\mathbf{y} = [y_1, \dots, y_m]$.

Dæmi:

  1. Hitastig sem fall af tíma á einni af fjölmörgum veðurstöðvum sem eru reknar af Veðurstofu Íslands.
  2. Spenna mæld yfir tvo punkta í einhvers konar rafrás.
  3. Styrkleiki merkis í varmageislunarmæli (e. bolometer) í örbylgjusjónauka.

Gildin sem eru lesin út breytast venjulega eitthvað með hverri mælingu. Þessi mæling hefur ákveðna óvissu og hugsanlega gæti leynst einhver mæliskekkja.

Ath:¶

  • Tímaröð er oft einhvers konar mælingar sem hefur verið raðað í tímaröð 🤔
  • Tíðni mælinganna er oft föst fyrir alla tímaröðina en það þarf þó ekki að vera
  • Oft má nota gögnin í tímaröðinni til að lýsa samfelldu falli einhvers konar eðlisfræðilegra eiginleika

Tímaraðagreining snýst of um að finna bestu mögulegu lýsingu á kerfinu sem mæligögnin lýsa. Það er ekki alltaf ljóst hvaða aðferð er besta til að greina gögnin. Það er því mikilvægt að skilja vel hvaða aðferðir eru til staðar og hvernig þær virka.

Tímaraðagreining (IÐN113F) kafar talsvert dýpra í þessi fræði.

Tölfræðilegt sjónarhorn¶

Við getum litið á tímaröð sem runu slembibreytna (e. random variables) sem sóttar eru úr einhvers konar líkindadreifingu (e. probability distribution). Það er hugsanlega einhvers konar fylgni (e. correlation) á milli slembibreytnanna. Dæmi:

  • Teningakast: Sérhvert kast lýsir óháðum atburði, engin fylgni á milli mælinga.
  • Hitastig: Hér getur verið sterkt fylgni á milli mælinga eftir því hvað líður langur tími á milli mælinga. Það er til dæmis sterk fylgni á milli mælinga ef við mælum hitastigið inni í þessu herbergi á sekúndufresti.

Ástandslýsing (e. dynamic system perspective)¶

Við notum tímaraðir til þess að öðlast skilning á eðlisfræðilegu kerfi. Við getum t.d. mælt sjávarhita sem fall af staðsetningu og tíma í Norður Atlantshafi til þess að smíða líkan sem lýsir hegðun makríls.

Við getum gefið okkur að þessum kerfum sem við erum að skoða megi lýsa með einhvers konar safni af breytum $x_1, x_2, \ldots, x_n$. Tímaröðin okkar $y_1, y_2, \ldots, y_n$ gerir okkur hugsanlega kleift að skorða þau mögulegu gildi sem breytur líkansins taka. Þetta mætti kalla ástandslýsing (e. dynamic system perspective).

Í þessu dæmi mætti t.d. ímynda sér að hver mæling í tímaröðinni $y_i$ megi reikna með óskilgreindu falli $f(t_i, x_1, \ldots, x_n)$. Verkefnið okkar er þá að finna fallið $f$ (sem sagt skilgreina líkan) út frá gögnunum sem við erum með í höndunum.

Leitni (eða þróun, e. trend) lýsir almennri stefnu tímaraðarinnar.

  • Hún getur aukist eða minnkað á mismunandi vegu yfir tíma (línulega, veldisvaxandi o.s.frv.).

Jafnvægi tímaraða¶

Jafnvægi (e. stationarity) tímaraðar lýsir því hvort að líkindadreifingin sem stjórnar tímaröðinni sé að breytast með tíma. Ef tímaröð er í jafnvægi yfir eitthvert tímabil er líkindadreifingin ekki að breytast.

Hver eru einkenni jafnvægis?¶

Tímaröð er sögð vera í jafnvægi ef að það eru engar breytingar á kerfinu sem framkallar tímaröðina. Það eru til mismunandi jafnvægisskilyrði:

  • Sterk jafnvægiskilyrði
  • Veik jafnvægisskilyrði

Ath: Við gerum oft ráð fyrir stöðugleika þegar við vinnum með tímaraðir en hvernig prófum við jafnvægi?

Sterk stöðugleikaskilyrði¶

$\newcommand{\set}[1]{\mathcal{#1}}$

Slembiferli $X(t) : t \in \mathcal{T}$ er sagt vera í jafnvægi ef, fyrir öll $t_1, t_2, \dots, t_n \in \mathcal{T}$ og $h$ þannig að $t_1 + h, t_2 + h, \dots, t_n + h \in \set{T}$, gildir að

$$ (X(t_1), X(t_2), \dots, X(t_n)) \overset{D}{=} (X(t_1+h), X(t_2+h), \dots, X(t_n+h)) $$

þar sem $\overset{D}{=}$ táknar að dreifingarnar eru jafnar.

Með öðrum orðum helst sameiginleg dreifing hvaða safns mælinga sem er í ferlinu óbreytt óháð því hvenær þær eru teknar.

Það er afar erfitt að sannreyna sterkt jafnvægi tímaraða, sérstaklega þegar aðeins er til takmarkað magn gagna.

Af þessari ástæðu er veikur stöðugleiki oftast kannaður.

Veik stöðugleikaskilyrði¶

Tímaröð $X$ uppfyllir veik stöðugleikaskilyrði ef:

  1. Meðaltal tímaraðarinnar er fast yfir tíma:
    $$ E[X(t)] = m, \quad \forall t \in \mathcal{T} $$

  2. Dreifnin er endanleg:
    $$ E[X(t)^2] < \infty, \quad \forall t \in \mathcal{T} $$

  3. Samdreifni (e. covariance) $X(t)$ og $X(t+h)$ ræðst aðeins af $h$, þ.e. er tímaskipt óbreytanlegt.

Veik stöðuleikaskilyrði eru uppfyllt ef tímaröðin uppfyllir skilyrði um sterkan stöðugleika, en ekki öfugt.

Dæmi um tímaröð sem uppfyllir veik stöðugleikaskilyrði¶

Eiginfylgni¶

Eiginfylgnifallið (e. autocorrelation, ACF), $\rho (k)$, mælir fylgni tímaraðar, $X(t)$, við sín eigin töfðu (e. lag, delay) gildi:

$$ \rho(k) = \frac{\sum_{t=k+1}^{N} (X(t) - \mu)(X(t-k) - \mu)}{\sum_{t=1}^{N} (X(t) - \mu)^2} $$

þar sem:

  • $\mu$ er meðaltal tímaraðarinnar
  • $X(t)$ er gildi tímaraðarinnar á tíma $t$
  • $k$ er töfin (e. lag)

Gildi nálægt $1$ eða $-1$ benda til sterkrar fylgni, en gildi nærri $0$ benda til veikrar fylgni.

Athugið að það er hægt að skrifa eiginfylgnina sem $$ ACF(k) = \frac{E[(X(t) - \mu]E[(X(t-k) - \mu]}{\sigma^2} $$ þar sem $\sigma^2$ er dreifni (e. variance) tímaraðarinnar. Hér stendur $ACF$ fyrir autocorrelation function.

ATH: Eiginfylgni (e. autocorrelation) og eiginsamdreifni (e. autocovariance) eru ekki sami hluturinn.

Eiginfylgni er eitt af fyrstu hugtökunum sem eru kynnt í umfjöllun um tímaraðagreiningu. Þetta hugtak fær sérstaka athygli í fjármálaheiminum þar sem fólk leitar stundum að lotubundunni hegðun í gögnum með miklu suði.

Við skulum skoða dæmi eiginfylgni fyrir sínusbylgju með suði fyrir nokkur gildi á þeirr töf sem við veljum.

# Gervigögn
np.random.seed(11)
n = 100  # Fjöldi punkta
n_periods = 5
noise_amp = 0.1
time_series = np.sin(np.linspace(0, n_periods*2*np.pi, n)) \
    + np.random.normal(0, noise_amp, n)  # Sínusbylgja með suði

# Fall sem reiknar eiginsamdreifni
def autocovariance(ts, lag):
    """Computes the autocovariance of a time series for a given lag."""
    ts_mean = np.mean(ts)
    n = len(ts)
    return np.sum((ts[:n-lag] - ts_mean) * (ts[lag:] - ts_mean)) / n

# Fall sem reiknar eiginfylgni
def autocorrelation(ts, lag):
    """Computes the autocorrelation for a given lag using np.cov."""
    ts1 = ts[:-lag] if lag > 0 else ts
    ts2 = ts[lag:] if lag > 0 else ts
    cov_matrix = np.cov(ts1, ts2, bias=True)
    return cov_matrix[0, 1] / cov_matrix[0, 0]  # Normalize by variance

# Reiknum eiginsamdreifni fyrir nokkur gildi á töf
lags = np.arange(20)  # Skoðum töf á bilinu frá 0 til 19
autocov_values = [autocovariance(time_series, lag) for lag in lags]

# Reiknum eiginfylgni fyrir nokkur gildi á töf
lags = np.arange(0, 50)
autocorr_values = np.array([autocorrelation(time_series, lag) for lag in lags])

# Teiknum upp
plt.figure(figsize=(8, 4))
fig, ax = plt.subplots(1,2, figsize=(10, 3))
ax[0].plot(time_series)

ax[0].set_xlabel("Tími [s]")
ax[0].set_ylabel("Gildi")

ax[1].stem(lags, autocorr_values)
ax[1].set_xlabel("Töf")
ax[1].set_ylabel("Eiginfylgni")

plt.show()

Hvítt suð¶

Suð í tímaröðum getur verið af ýmsum toga alveg eins og suð í náttúrunni. Í eðlisfræðilegum kerfum tengjum við suð við einhvers konar handhófskennd ferli eins og fossanið eða hljóðið sem berst frá útvarpi þegar það nær ekki sambandi við útvarpsstöð.

Það er oft gagnlegt að brjóta suð upp í tíðniþætti. Niðurinn frá Gullfossi er frekar djúpur en tíðnin sem heyrist þegar heitt vatn seitlar inn á ofnakerfi er oft eitthvað hærri. Stundum er suð sett saman úr blöndu af ýmsum tíðnum með mismunandi styrkleika. Dæmi: glymur á fjölförnum veitingastað.

  • Eiginfylgnin er núll

Sveiflur og hlaupandi meðaltöl¶

Hlaupandi meðaltal er algeng aðferð til þess að draga úr suði í tímaröð. Dæmið fyrir neðan sýnir hvað gerist þegar við beytum hlaupandi meðaltali á mælingar á sínusbylgju sem einkennist af frekar miklu suði.

np.random.seed(9)

# Gervigögn (sínusbylgja með suði)
x = np.linspace(0, 10, 100)
y_true = np.sin(x)  # Sínusbylgjan
noise = np.random.normal(0, 0.3, size=x.shape)  # Suð með Gauss-dreifingu
y_noisy = y_true + noise  # Merki með suði

# Skilgreinum fall sem býr til hlaupandi meðaltal
def moving_average(data, window_size):
    """Applies a simple moving average filter to the data."""
    return np.convolve(data, np.ones(window_size)/window_size, mode='valid')

# Sléttum úr gögnunum með hlaupandi meðaltali
window_size = 3  # Stærð gluggans
y_smooth = moving_average(y_noisy, window_size)

# Hlaupandi meðaltal byggir á földun, við þurfum því að stytta inntaksbreytuna
x_smooth = x[:len(y_smooth)]

# Teiknum upp graf
plt.figure(figsize=(10, 5))
plt.plot(x, y_noisy, label='Gögn með suði', ls='dotted', alpha=0.9)
plt.plot(x, y_true, label='Sínusbylgjan', ls='dashed', alpha=0.8)
plt.plot(x_smooth, y_smooth, label='Hlaupandi meðaltal', color='tab:red')
plt.legend()
plt.xlabel("X")
plt.ylabel("Y")
plt.title("Áhrif hlaupandi meðaltals")
plt.show()
